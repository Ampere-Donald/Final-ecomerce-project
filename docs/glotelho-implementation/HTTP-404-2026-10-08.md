# Réponses HTTP des routes inconnues

Défaut reproduit en production le 8 octobre : /page-inexistante-newoteg-audit renvoyait 200 sans noindex, alors que cette route n'existe pas dans React. Le fallback SPA est utile pour les routes connues mais ne doit pas annoncer une page inconnue comme existante.

Le Worker transforme uniquement une réponse HTML 200 de l'asset binding, sur GET/HEAD et route inconnue, en 404 avec noindex et no-store. Le corps React reste présent pour afficher l'aide existante. Les assets non HTML, redirections, erreurs et proxys API/uploads sont préservés. Les protections privées s'appliquent aussi aux sous-chemins privés inconnus.

documentRoutes.js décrit les chemins définis par App.jsx ; un test extrait toutes ses routes explicites et vérifie leur reconnaissance, y compris paramètres, casse et slash final. Ce classement ne vérifie pas l'existence d'un produit ou projet : les 404 des références dynamiques restent à traiter séparément. Ce changement ne livre pas un rendu serveur complet ni ne prouve le référencement.

Validation : tests Node dédiés et runtime local Miniflare/workerd, réseau extérieur interdit. Les 11 pages privées conservent leurs en-têtes, quatre routes publiques restent 200, trois routes inconnues deviennent 404, image inchangée octet par octet. Le pilote de recette accepte dist-release et utilise le convertisseur officiel d'options quand Miniflare 5 est installé.
